== Architecture Tour on OpenShift

Your environment is fully deployed on a shared OpenShift cluster. Each learner has a personal CTFd instance for this facilitator-training lab.

=== Log into the OpenShift Console

. Open the OpenShift Console: {ocp_console_url}
. Log in with your instructor credentials: `{keycloak_username}` / `{password}`.

== Open the Instructor Workspace

. In Gitea, open your *`aia-instructor`* repository under your own account. Module 3 uses the instructor toolkit; Module 4 uses the other repository, `ansible-survival-kit`.
. Click *Code → HTTPS* and copy the clone URL. Your URL has this form:
+
[source,text,subs="attributes"]
----
{gitea_url}/{gitea_username}/aia-instructor.git
----
. Open {devspaces_url}, select *Create Workspace*, and paste that HTTPS URL.
. Use the repository's `.devfile.yaml` and trust the repository when prompted. Wait for the editor and any collection-installation startup task to finish. The devfile supplies Ansible, Lint, Navigator, and related utilities.
. If Git requests authentication, use `{gitea_username}` and your provisioned lab password.
. Open *Terminal → New Terminal* and verify the tools:
+
[source,bash]
----
ansible --version
ansible-lint --version
ansible-navigator --version
----
. Paste the `oc login` command saved from the OpenShift console into this terminal. Run `oc whoami` and confirm it reports your instructor account. Keep this token available for the survival-kit workspace in Module 4 as well.

=== Configure Your Vault Password

Your organizer supplies the vault password for the encrypted files in your instructor repository. It is separate from your OpenShift login token and your service login password.

In the workspace terminal, prepare the password file:

[source,bash]
----
cd /projects/aia-instructor
umask 077
vim .vault-password
----

Enter only the organizer-provided password on one line, then save and exit. Verify it:

[source,bash]
----
chmod 600 .vault-password
ansible-vault view roles/ctfd/vars/flags.yml
----

The instructor devfile sets `ANSIBLE_VAULT_PASSWORD_FILE` to `/projects/aia-instructor/.vault-password`. Keep this file local to your workspace; never commit it or include it in an image. A newly created workspace may require this setup again.

== Deployment Artifacts Walkthrough

Open *`deploy.yml` at the root of your Gitea `aia-instructor` repository*. Explore its pre-tasks and follow the `ctfd` and `verifier` roles:

[source,text]
----
aia-instructor/
  ├── deploy.yml                  → Full deployment and CTFd archive import
  ├── update-challenges.yml       → Update challenge content through the CTFd API
  ├── generate-handouts.yml       → Generate participant handouts
  └── roles/
      ├── ctfd/
      │   ├── tasks/              → Infrastructure, players, archive, and upload tasks
      │   └── vars/
      │       ├── challenges.yml
      │       ├── challenges_advanced.yml
      │       └── flags.yml       → Vault-encrypted answers
      └── verifier/               → Challenge verification service
----

The shared platform was provisioned separately. The toolkit's `deploy.yml` does not represent every platform provisioning step; do not assume it installs AAP or Dev Spaces.

The `ctfd` role deploys CTFd, MariaDB, and Redis; configures players and Gitea; and builds and imports a CTFd configuration archive. Some tasks also change cluster-wide configuration. The `verifier` role deploys the service that checks automation results on managed nodes.

=== Deployment Input Files

Review the input files named by the current toolkit. These are private inputs, not files to commit:

[cols="1,3",options="header"]
|===
| File | Purpose
| `rosa.creds` | Legacy resource-claim input expected by `deploy.yml` and `update-challenges.yml`. Their pre-tasks extract `rosa_openshift_*` fields and log in again.
| `workshop.creds` | Workshop input expected by `deploy.yml` to obtain the player count.
| `player.creds` | Cached player passwords and verification tokens, generated on the first run and reused on later runs.
|===

Reusing player credentials does *not* preserve CTFd scores when a configuration archive is restored. Encrypted answers are in `roles/ctfd/vars/flags.yml`. The managed node VM and SSH access are provisioned separately.

=== Verify the Playbook Before Playing

First validate the toolkit syntax:

[source,bash]
----
cd /projects/aia-instructor
ansible-playbook deploy.yml --syntax-check
----

[WARNING]
====
A full `deploy.yml` run imports a CTFd configuration archive and *resets the target CTFd environment*. Existing scores, submissions, and progress are lost. Complete any approved deployment exercise *before Module 4*.
====

The current upstream playbook expects legacy `rosa.creds` and `workshop.creds` inputs and can change cluster-wide resources. A personal `oc login` token alone does not make it ready for this shared training cluster. The facilitator must confirm an isolated target, compatible input files, permissions, and CTFd settings before you execute it. Do not substitute the shared leaderboard's administrator credentials.

When the facilitator has supplied and verified that isolated deployment configuration, run from the repository root:

[source,bash]
----
ansible-playbook deploy.yml
----

Confirm the run succeeds and the intended CTFd board is accessible before Module 4. If compatible inputs and an isolated target have not been supplied, complete the syntax check and artifact review only; full deployment verification remains blocked until the toolkit is adapted for this training environment.

== Preparing a Customer Event

Arrange a pre-deployed environment with adequate lead time, verify service access and challenge content, then distribute participant handouts. Normally participants share the customer event's CTFd board; the separate boards in this training lab let learners practice customization independently.

== Key Takeaways

* Use `aia-instructor` for deployment and customization; use `ansible-survival-kit` to play the challenges in Module 4.
* Save your personal OpenShift login token and use it in your Dev Spaces terminal.
* Inspect the root `deploy.yml`, its roles, and its actual input files before running it.
* Full CTFd archive deployment resets progress. Perform an approved deployment exercise before playing.
